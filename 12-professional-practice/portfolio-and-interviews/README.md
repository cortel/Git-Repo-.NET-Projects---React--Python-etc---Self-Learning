# Portfolio and interview explanations

Status: planned. Practice alongside completed features in [Start here](../../00-roadmap/start-here.md).

After a working change, answer one question without reading a reference. Explain the problem, decision, alternative, failure behavior and evidence in about two minutes. Then check the answer and reproduce any exposed gap in code.

- [ ] Explain one .NET async/cancellation issue using a runnable example.
- [ ] Explain an SQL query plan and concurrency conflict from the project.
- [ ] Defend a domain boundary and one decision to avoid an unnecessary technology.
- [ ] Walk through a traced failure, rollback or recovery exercise.
- [ ] Explain an AI quality failure using evaluation and retrieval evidence.
- [ ] Give an example of review feedback, uncertainty in an estimate and a changed requirement.
- [ ] Separate simulated leadership practice from actual team experience in portfolio stories.

Use one question source from [curated links](../../14-learning-material/curated-links.md) at a time. Interview recall complements implementation; completion percentages on external sites are not evidence that the application works.
