# Intermediate to Senior and Lead learning path

Use your current ability as the starting point. The goal is independent delivery of maintainable systems and the ability to improve a team's decisions and execution. Job titles vary; this is an evidence-based development plan, not a guaranteed promotion checklist.

## Diagnose before studying

Try a small feature without following a tutorial: a .NET API plus React form with persistence, authorization and a failure case. Review a flawed PR, explain an SQL query plan, diagnose a seeded slow request and discuss a changed business requirement. Record what you can do independently, what needs reference material and what requires help. Revisit only the foundation topics exposed by this diagnostic.

## Active learning path

Follow [Start here](./start-here.md) for the single six-stage progression. Use the rubric below to assess demonstrated competence; it is not a second sequence of projects. Practice review, communication and mentoring alongside the same application.

## Working proficiency rubric

For each row below, record a link to actual evidence and rate the current behavior: 0 = not demonstrated; 1 = can explain or complete with guidance; 2 = can execute independently and explain tradeoffs; 3 = can guide others, handle changing constraints and improve the team's outcome. This rubric is a local learning aid.

| Competency | Senior-oriented evidence | Lead-oriented extension |
| --- | --- | --- |
| Coding and refactoring | Deliver readable changes with tests and controlled scope | Establish useful conventions and improve review quality |
| TDD and verification | Choose tests that catch meaningful failures | Improve team feedback speed and diagnose coverage gaps |
| Domain modeling | Protect invariants and explain model boundaries | Facilitate discovery and resolve cross-team language conflicts |
| Architecture | Compare alternatives against measured requirements | Lead reviews, manage evolution and revisit decisions with evidence |
| Data and performance | Explain plans, locking, allocations and bottlenecks | Balance capacity, cost and migration across the product |
| Security and reliability | Apply authorization, threat models and recovery checks | Shape controls, ownership and incident response across systems |
| DevOps and operations | Deploy, observe, rollback and restore independently | Improve team delivery and operational readiness |
| AI systems | Bound, evaluate and operate an agent workflow | Define governance, rollout criteria and platform ownership |
| Collaboration | Give actionable feedback and communicate risk early | Mentor, negotiate scope and enable other developers |
| Product judgment | Connect technical choices to user outcomes | Prioritize strategy/debt with stakeholders and measure results |

Aim for independent execution in the core technical areas, then demonstrate the leadership extensions repeatedly. A simulated exercise should be labeled as simulated; actual team work provides stronger evidence than a self-score.
